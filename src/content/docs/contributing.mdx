## Development Setup

### Prerequisites

- Python 3.13+
- Node.js 20+ (for frontend development)
- Git

### Getting Started

```bash
# Clone the repository
git clone https://github.com/GreenKubeCloud/GreenKube.git
cd GreenKube

# Install uv (if not already installed)
pip install uv
# or: curl -LsSf https://astral.sh/uv/install.sh | sh

# Create virtual environment and install all dependencies (dev + test)
uv sync
source .venv/bin/activate  # Linux/macOS
# .venv\Scripts\activate   # Windows

# Install pre-commit hooks
pre-commit install

# Run tests to verify everything works
uv run pytest
```

### Frontend Development

```bash
cd frontend
npm install
npm run dev    # Start dev server with hot reload
npm run build  # Build for production
```

## Code Guidelines

### Architecture Rules

<Aside type="caution">
  **Critical:** The `src/greenkube/core/` directory must NEVER depend on specific storage implementations. Always use repository abstractions.
</Aside>

- **Database Agnosticism:** Use repository interfaces, never import storage-specific code in `core/`
- **Factory Pattern:** Instantiate repositories via `core/factory.py`
- **Dependency Injection:** Pass repositories to use cases as parameters

### Async Best Practices

- **All I/O is async:** Use `async def` for network, database, and file operations
- **Always await:** Never use sync wrappers for async operations
- **Concurrent execution:** Use `asyncio.gather` for parallel operations
- **Connection pooling:** Reuse HTTP clients and database pools

### Error Handling

- **Fail closed and explain why.** A value that cannot be read is missing, never zero or a silent default; a gate whose input cannot be read is `not_available`, never a pass. Estimated inputs are flagged (`is_estimated` with its reasons).
- **One failure stays local.** A failing source, loop tick or collection window is reported with context and retried; it never stops the others.
- **Standard logging:** Use `logging.getLogger(__name__)`

### Code Quality

```bash
# Format code
uv run ruff format .

# Lint code
uv run ruff check .

# Auto-fix lint issues
uv run ruff check --fix .

# Type-check with Pyrefly
uv run pyrefly check

# Run tests
uv run pytest

# Run tests with coverage
uv run pytest --cov=greenkube --cov-report=html
```

### Logging Levels

| Level | Use Case |
|-------|----------|
| `DEBUG` | Detailed flow, cache hits, parsing details |
| `INFO` | Major pipeline events, collection start/end |
| `WARNING` | Recoverable issues, fallback to defaults |
| `ERROR` | Failures requiring attention |

## Commit Convention

Follow [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add GPU power profiling
fix: handle missing node labels gracefully
docs: add storage backend comparison
test: add unit tests for rightsizing recommendations
refactor: extract zone mapping to utility module
perf: optimize batch database inserts
```

## Pull Request Process

1. **Fork** the repository
2. **Create a branch** from `dev` (the integration branch): `git checkout dev && git checkout -b feat/my-feature`
3. **Write tests** for your changes (TDD approach)
4. **Run the test suite** and ensure all tests pass
5. **Format and lint** your code with Ruff
6. **Commit** with a conventional commit message
7. **Push** to your fork and open a Pull Request targeting `dev`
8. **Describe** your changes and link relevant issues

### PR Checklist

- [ ] Tests pass (`pytest`)
- [ ] Code is formatted (`ruff format --check .`)
- [ ] Code passes lint (`ruff check .`)
- [ ] New features have tests
- [ ] Documentation is updated (if applicable)
- [ ] Commit messages follow conventional commits

## Where to Start

- **A new recommendation source.** Implement a `Source` (discover, health, collect) that emits signals, package it under the `greenkube.sources` entry point group, and run the contract test suite. See [Sources overview](/sources/overview/#writing-your-own-source) and the [example package](https://github.com/GreenKubeCloud/GreenKube/tree/main/examples/greenkube-source-example).
- **A new GitOps layout.** Unsupported layouts fail closed with a typed reason; the [GitOps delivery](/concepts/gitops-delivery/#supported-layouts) page lists what is supported today.
- **The end-to-end loop.** `make e2e` runs the whole loop on Minikube with a sample app, Argo CD, Flux and Gitea ([Quick Start](/getting-started/quickstart/)).

The repository's [CONTRIBUTING.md](https://github.com/GreenKubeCloud/GreenKube/blob/main/CONTRIBUTING.md) is the reference for the development workflow.
