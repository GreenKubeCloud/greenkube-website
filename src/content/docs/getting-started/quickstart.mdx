This guide will have GreenKube up and running in your cluster in under 5 minutes.

## Prerequisites

Before you begin, make sure you have:

- ✅ A running **Kubernetes cluster** (Minikube, EKS, GKE, AKS, etc.)
- ✅ **Helm 3** installed ([install guide](https://helm.sh/docs/intro/install/))
- ✅ **kubectl** configured to access your cluster
- ✅ **Prometheus** deployed in your cluster (e.g., via kube-prometheus-stack)
- ✅ **OpenCost** deployed for cost data (optional but recommended)

<Aside type="tip">
  Don't have Prometheus yet? The most common setup is the **kube-prometheus-stack** Helm chart, which includes Prometheus, Grafana, and commonly used exporters.
</Aside>

## Try the Demo First (No Cluster Required)

Want to explore GreenKube without any infrastructure? Start with **Demo Mode** — it loads 30 days of realistic data for the fictional **GreenOptic** company: 22 pods across 5 namespaces with carbon emissions, costs, recommendations, and a pre-populated savings ledger.

<Tabs>
  <TabItem label="🐳 Docker (no cluster needed)">

The fastest way to try GreenKube. Only Docker is required — no Kubernetes, no Prometheus, no setup.

```bash
docker run --rm -p 9000:9000 \
  greenkube/greenkube:latest \
  demo --no-browser --port 9000
```

Open [http://localhost:9000](http://localhost:9000) in your browser. Press `Ctrl+C` to stop.

  </TabItem>
  <TabItem label="☸️ Kubernetes (standalone pod)">

If you have a cluster available, you can run the demo as a temporary pod:

```bash
kubectl run greenkube-demo \
  --image=greenkube/greenkube:latest \
  --restart=Never \
  --command -- greenkube demo --no-browser --port 9000

kubectl wait --for=condition=Ready pod/greenkube-demo --timeout=60s
kubectl port-forward pod/greenkube-demo 9000:9000
```

Open [http://localhost:9000](http://localhost:9000) in your browser.

```bash
# Clean up when done
kubectl delete pod greenkube-demo
```

  </TabItem>
</Tabs>

<Aside type="tip">
  Demo mode does not require Prometheus, OpenCost, or any live cluster. It's a great way to evaluate the dashboard and understand what metrics GreenKube collects before committing to a full installation.
</Aside>

## Installation

<Steps>

1. **Add the Helm repository and install**

   ```bash
   helm repo add greenkube https://GreenKubeCloud.github.io/GreenKube
   helm repo update
   helm install greenkube greenkube/greenkube \
     -n greenkube \
     --create-namespace
   ```

   This deploys the data collector, REST API, web dashboard, and a PostgreSQL database — all in one command.

2. **Wait for pods to be ready**

   ```bash
   kubectl get pods -n greenkube -w
   ```

   You should see:
   ```
   NAME                         READY   STATUS    RESTARTS   AGE
   greenkube-7b5f8c9d6-x2k4p   2/2     Running   0          30s
   greenkube-postgres-0         1/1     Running   0          30s
   ```

3. **Access the dashboard**

   ```bash
   kubectl port-forward svc/greenkube-api 8000:8000 -n greenkube
   ```

   Open [http://localhost:8000](http://localhost:8000) in your browser.

4. **(Optional) Add an Electricity Maps token**

   For accurate, region-specific carbon data instead of the default 500 gCO₂e/kWh:

   ```bash
   helm upgrade greenkube greenkube/greenkube \
     -n greenkube \
     --set secrets.electricityMapsToken="YOUR_TOKEN_HERE"
   ```

   Get a free token at [electricitymaps.com](https://www.electricitymaps.com/).

5. **Run your first report**

   ```bash
   GREENKUBE_POD=$(kubectl get pods -n greenkube \
     -l app.kubernetes.io/name=greenkube,app.kubernetes.io/component=app \
     -o jsonpath='{.items[0].metadata.name}')

   kubectl exec -it $GREENKUBE_POD -n greenkube -- greenkube report --daily
   kubectl exec -it $GREENKUBE_POD -n greenkube -- greenkube recommend
   ```

</Steps>

## What You'll See

- **Dashboard** — KPI cards showing total CO₂ emissions (Scope 2 + Scope 3), costs, energy consumption, sustainability score (0–100), and active pods. Time-series charts and namespace breakdown.
- **Metrics** — Interactive table with per-pod metrics: energy (CPU-based), cost, CO₂e, embodied CO₂e, CPU, memory, network, disk, and restarts.
- **Nodes** — Cluster node inventory with CPU/memory capacity, hardware profiles, cloud provider info, and utilization.
- **Recommendations** — Actionable suggestions with Active, Ignored, and Realized Savings views. Projected annual CO₂e and cost savings per recommendation, plus ignore/restore flows.
- **Report** — Time-range picker, namespace filter, granularity options, and direct CSV/JSON download for CSRD/ESRS E1 reporting.
- **Settings** — Service health overview (Prometheus, OpenCost, Electricity Maps, Boavizta), runtime config updates, K8s Secret persistence.
